# Independent election randomization

The built-in commit-log adapter now uses the stable `go.etcd.io/raft/v3 v3.6.0`
module. Go 1.23 or newer is required. Docker builders and the CI linter have been
updated to match. Raft types remain confined to `internal/lsm/commitlog`; public
provider contracts, peer envelopes, and server configuration are unchanged.

## Failure and fix

The three-process smoke test exposed repeated split votes both at startup and
after stopping the elected leader. A retained 20-run baseline had three election
convergence failures. Diagnostic runs showed all three processes selecting the
same election timeout sequence for 16 consecutive rounds:

```text
11, 15, 10, 17, 17, 15, 12, 16, 12, 14, 17, 11, 11, 15, 15, 18
```

The old v3.5.13 implementation seeds a process-local pseudo-random generator from
wall-clock time. Identical sequences are consistent with colliding seeds; the
seed values themselves were not instrumented. This was not just a missed status
poll: node logs showed repeated vote rejection, and status requests at timeout
completed in less than a millisecond.

The upstream [randomization fix](https://github.com/etcd-io/raft/commit/780bbb2b0f203bb59f4bf44f2a1df3b9c0d12ce9)
uses `crypto/rand` for election timeouts to break ties. The released
[v3.6.0 implementation](https://github.com/etcd-io/raft/blob/v3.6.0/raft.go)
contains that fix. We consume the upstream implementation through our existing
adapter instead of patching private library state or adding a second election
algorithm. Election/tick intervals and smoke-test deadlines were not increased.
Temporary reflection and persistence-timing diagnostics were removed.

## Validation and compatibility

- The [three-process smoke test](three-process-smoke.md) checks startup elections,
  replacement elections, quorum writes/deletes, offline-node catch-up, full
  restart, and actual persisted values on every node.
- `TestEtcdRaftReadsLegacyV3513Storage` opens a checked-in file generated by the old
  adapter/library. It checks original entries and sequences, commits new data,
  and reopens again. The simple JSON Raft storage format is unchanged.
- Package, integration, and race tests remain merge gates.

This does not establish rolling mixed-version cluster compatibility. Stop all
nodes cleanly before upgrading an experimental cluster, preserve its data, and
restart all nodes with the same binary. Production snapshots, membership changes,
online read consistency, crash durability, and transport security remain separate
milestones. A repeated smoke pass is evidence for this workflow, not proof against
every possible election or network failure.
